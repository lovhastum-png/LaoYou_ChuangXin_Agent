## 1. 背景与范围

用户提供一段手机拍摄的走廊视频，要求验证 `backend/pose` 跌倒检测侧车的实际表现。

侧车的判定链路（详见 [`backend/pose/README.md`](../../backend/pose/README.md)）：

```
姿态几何（横卧：躯干偏离竖直轴 ≥ 62°）
        AND
运动学（坠落：鼻部下降速度 ≥ 0.8 画面高/秒  或  躯干角速度 ≥ 600°/秒）
        AND
时序（连续 5 帧横卧确认）+（横卧开始前 2.0 秒内出现过坠落证据）
```

本文只回答一个问题：**这段视频，我们检出得了吗？检不出是为什么？**

## 2. 结论摘要

| 项目 | 结果 |
|---|---|
| 视频真值 | **跌倒**（站立行走 → 约 2.8s 前扑 → 2.97s 沉出画面下沿） |
| 基线检测结果 | ❌ **漏报（0 告警）** |
| 漏报根因 | 坠落信号成立（峰值 0.978，连续 5 帧越过 0.8 阈值），但**躯干角全程最大仅 21.1°**，远达不到 62° 的横卧阈值，于是状态机的 AND 条件永不满足 |
| 为什么躯干角上不去 | 人是**朝镜头方向**扑倒的，在身体转到横卧之前就从画面下沿消失了；此后模型看不到人（`present=0`），几何量全部为 0 |
| 候选修复 | 新增判据「**坠落并沉出画面**」：消失前髋部已抵近画面下沿 + 2 秒内有坠落证据 → 判为跌倒 |
| 修复后 | ✅ **t=3.00s 正确告警** |
| 修复的全量代价 | ⚠️ URFD 全量：召回 0.700→0.733，精确 **0.724→0.667**，F1 **0.712→0.698** —— **净负** |
| 修复的默认状态 | **关闭且不建议开启**（`detect_frame_exit_fall=False`） |

## 5. 根因分析

状态机的确认条件是**坠落与横卧的硬 AND**（`detector.py::_evaluate`）：

```python
if not feat.present:            # 人一出画就整体清零
    self._lying_frames = 0
    ...
    return False, "画面内无有效人体"

if feat.lying:                  # 需要躯干角 ≥ 62° 才能累加确认帧
    self._lying_frames += 1
    ...
```

这段视频里：

1. **坠落这一支完全成立** —— idx 85–89 连续 5 帧 `descent ≥ 0.8`，峰值 0.978，`falling=1`，`_last_falling_at` 被正确更新。
2. **横卧这一支从始至终不成立** —— 人体朝镜头扑倒时，在水平化之前就从画面下沿滑出去了。`nose_y` 从 0.50 升到 0.672、`hip_y` 已达 1.000，躯干还只偏了 21.1°；下一帧整个人消失，几何量直接归零。
3. 两个 `if` 都进不去 → 状态长期停在 `upright` → **横卧确认帧数永远是 0** → 冷却与告警都不触发。

也就是说，**这不是阈值调参能解决的问题**：把 `torso_angle_threshold` 从 62° 降到 21° 会立刻在「坐下/弯腰」上疯狂误报，而真正缺的是「人体在画面里根本来不及转体」这条路径的判据。README 第 5 节其实已经预警过这个场景（"人跌倒时常冲出画面"），本次是第一次拿到实证。

## 6. 候选修复与验证

### 6.1 新增判据

在 `DetectionConfig` 增加两个字段（**默认关闭**）：

| 字段 | 默认 | 含义 |
|---|---|---|
| `detect_frame_exit_fall` | `False` | 是否启用「坠落并沉出画面」判据 |
| `exit_frame_hip_threshold` | `0.95` | 髋部归一化纵坐标达到该值即视为「已抵近画面下沿」 |

在 `FallDetector._evaluate` 的「人不在画面内」分支里，把「沉出画面」作为横卧确认的**等价路径**：

```
人出画  AND  消失前最后一帧 hip_y ≥ 0.95  AND  2.0 秒内出现过坠落证据  AND  不在冷却期
   → 判定为跌倒
```

同时新增 `_last_present_hip_y`，在 `feed()` 里每次画面内有人时刷新，供人消失后回溯。

## 7. 结论与边界

1. **基线的这次漏报是设计边界暴露，不是代码 bug。** 状态机假设「跌倒 = 快速坠落 + 横卧」，而朝镜头方向扑倒时人体在转成横卧前就出了画面，这条路径原本没有被覆盖。
2. **修复本身是有效的、低风险的**：9 段样本上召回 0.667→0.833，精确不降。
3. **但它与机位强相关，所以默认关闭。** 开启前必须在本场地补拍三类日常动作做误报验证：
   - 快速走到镜头前并从画面下沿离开
   - 快速下蹲捡物后起身
   - 坐到低凳 / 沙发
   只要这三类不产生误报，再把 `detect_frame_exit_fall` 打开。
4. **居家部署仍须重新标定。** 本项目基线用 URFD 近景风格标定，`descent_speed_threshold=0.8` 对固定广角吊装机位偏高。换机位一律先跑 `backend/pose/calibrate.py`。
5. **不要因此把这条判据当成通用兜底。** 它只覆盖「快速坠落 + 沉出画面」这一种形态；慢速软倒、侧向倒地、被遮挡的跌倒仍然不在覆盖范围内。
