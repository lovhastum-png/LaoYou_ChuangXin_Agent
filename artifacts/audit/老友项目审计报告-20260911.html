一、先说最要紧的两条

P0 数据库连不上时，后端进程直接崩溃（不是返回 503）
backend/app/db.py:48-54（pool_pre_ping=True）→ main.py:275-279 /api/health

这是我实测复现出来的问题，纯静态审计发现不了。create_engine(..., pool_pre_ping=True) 在 目标数据库不可达时，不会抛出可捕获的异常，而是让 Python 进程原地死亡—— 没有 traceback、没有日志、退出码 1。

对照实验（同一环境、同一连接串，只改引擎参数） 
无 pool_pre_ping   → 干净抛出 OperationalError，进程存活 ✅
带 pool_pre_ping   → 进程静默死亡，无任何异常输出 ❌
该现象同时解释了另一个反常表现：pytest 跑到 tests/test_static.py 会静默中断（9 个用例通过后 exit=1、无任何报错文字），因为该测试会启动 TestClient → 触发 lifespan → 连接数据库。
建议改法：① check_database() 与引擎连接加上显式 connect_timeout （实测加上 connect_args={'connect_timeout':3} 后行为恢复正常）； ② 评估是否真的需要 pool_pre_ping，若保留则必须在真实环境下回归"DB 拉闸"这一幕； ③ 把 /api/health 的 DB 故障路径做成明确的 503，而不是让 worker 挂掉—— 低配服务器上多 worker 被打挂会直接影响可用性。
P0 演示口令 Laoyou123! 被硬编码并无条件播种为真实账号
backend/app/db.py:106（seed_demo_data）← db.py:76-82 init_db() ← main.py:254 lifespan 每次启动调用

服务每次启动都会创建 elder / child / community / admin 四个账号，口令固定为 Laoyou123!，没有任何环境开关。任何能访问该服务的人用 admin / Laoyou123! 即可读取全部家庭的健康、作息、位置与摄像头快照。

同一口令还外溢到两处：

  • web/src/pages/LoginPage.vue:20 把它预填在输入框里，构建后任何人查看 JS 即可读到；
  • android/.../MainActivity.kt:569 在 APP 登录页明文打印全部演示口令。
建议改法：① 播种加显式演示开关（如 LAOYOU_DEMO=1），非演示环境不建账号； ② 口令移入环境变量，或首次启动生成随机口令打印到控制台；③ 前端去掉预填密码，安卓端仅 BuildConfig.DEBUG 时展示提示。这一条是当前最容易被真实利用的点。

二、P1：本轮应修

P1 摄像头/麦克风采集在离开页面后仍在继续
web/src/lib/useCameraSession.ts:6-17（模块级单例）｜ SafetyPage.vue:161-164 ｜ ElderHome.vue:145-148 ｜ App.vue:101 ｜ api.ts:80-102

useCameraSession 的状态与定时器全部定义在模块作用域（非组件作用域）。核实结果：

  • SafetyPage 的 onBeforeUnmount 只做 detachPreview() + 释放 URL，没有调用 camera.stop()；
  • ElderHome 卸载只清自己的时钟/播报定时器；App.vue 卸载只摘 popstate 监听；
  • 全项目 grep visibilitychange / pagehide / beforeunload → 零命中。

后果：在安全页点"启动本机预览"后切到其他页面，摄像头视频轨仍在， 每 30 秒上传一次快照、每 10 秒轮询一次设置会一直持续到手动停止或退出登录。

说明：跨页保活看起来是有意设计（App.vue:61-63 的 resumeCameraId、attachPreview 都在支持"切页回来预览还在"）。所以我不建议简单粗暴地卸载即停， 但"关标签/切到后台不停流"以及"在其他页面看不到任何采集中提示"是确定的缺口。

建议改法：在 useCameraSession 内监听 visibilitychange/pagehide， 页面隐藏时暂停采集或 stop()；若确实要跨页保活，则加一个全局"正在采集中"的常驻指示与一键停止入口。
P1 请求层没有超时、没有 401 拦截
web/src/lib/api.ts:80-102（request()）

核实：fetch 未传 signal、无 AbortController、无超时； 非 2xx 一律只抛 ApiError，没有针对 401 的清会话逻辑 （只有 App.vue:91-98 在启动时 api.me() 失败才清）。

两个直接后果：① TCP 被中间设备挂起时，各页面 try/finally 的 finally 永不执行， 老人端会永久停在"正在加载…"转圈且无法重试；② 会话过期（默认 7 天）后界面只报错不退回登录页。

建议改法：在 request() 内加 AbortSignal.timeout(ms)， 并在 status === 401 时 clearSession() + 派发全局事件由 App.vue 回登录页 （注意排除 /auth/login 与通话页的临时 token 调用）。
P1 会话 token 被写进 URL
web/src/App.vue:63（pushState('/call/{id}?token=...')）｜ api.ts:228-232（WS query 带 token）

进入通话时把 7 天有效的会话主 token 放进地址栏。CallPage.vue:211 虽然挂载后会 replaceState 清掉，但在此之前该 URL 已进入浏览器历史条目；期间任何子资源请求的 Referer、以及反向代理日志都可能带上它。WS 侧同样把 token 放在 query。

建议改法：改用后端签发的一次性、短 TTL 通话票据（进入 WS 后立即消费）， 不要复用长期会话 token；WS 可用子协议或首帧鉴权消息替代 query。
P1 打包脚本：敏感文件检查发生在压缩之后，防线形同虚设
scripts/build-package.ps1:222（Compress-Archive） vs :226-234（$forbidden 检查）

已核实执行顺序：先 Compress-Archive 生成 laoyou-windows-x64.zip， 之后才检查 runtime/local.env、runtime/database-credentials.json 等禁止文件。 一旦命中，throw 只是报错，含凭据的 zip 已经落在产物目录里。

建议改法：把禁止文件校验移到 Compress-Archive 之前； 并在压缩后追加一次"读取 zip 条目名再扫一遍"的二次校验。
P1 安卓端全局放开明文 HTTP
android/app/src/main/AndroidManifest.xml:15（android:usesCleartextTraffic="true"）

全局生效且无 networkSecurityConfig 收敛。APP 默认就是 http:// （MainActivity.kt:552 占位符），因此登录口令与后续 Authorization: Bearer 在局域网内是明文传输的。核实：安卓端权限申请本身规范（CAMERA/RECORD_AUDIO/POST_NOTIFICATIONS 均有 运行时申请），未多申请通讯录、位置等敏感权限。

建议改法：新增 network_security_config.xml，base-config 关闭明文， 仅对可信内网网段放行；若验收阶段必须保留任意 IP，至少在登录页加显著中文提示， 并在接口契约中记录该已知风险。
P1 前端未构建，导致静态页测试必然失败
web/dist 不存在（.gitignore:12 忽略）← backend/app/main.py:1205-1208 if web_dist.is_dir()

核实：web/dist 目录当前不存在。后端只在 web/dist 存在时才挂载 SPA 路由， 而 tests/test_static.py:9-16 断言 /reminders、/health 等返回 200 index.html， 因此该测试在不先 pnpm build 的机器上必然失败（这也是 pytest 中断的直接原因）。

建议改法：把该测试标记为 skipif(not web_dist.exists()) 并在前置说明中要求先构建， 或让测试自建临时 index.html 后再断言路由回退逻辑。
